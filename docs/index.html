Sign-in page? I know a guy.

Sign in to Captive Portals (hotel, airport, library and café Wi-Fi) while Windows keeps your DNS encrypted. Only the sign-in window uses the portal's DNS.

Encrypted DNS, with no exceptions

You've set Windows to encrypted DNS (DNS over HTTPS, e.g. NextDNS or Cloudflare), with fallback to plain DNS turned off. Then you join hotel Wi-Fi, and the sign-in page never appears: the network blocks encrypted DNS until you sign in, and you can't sign in without its DNS. Without CapPo, you're left with three choices, and each one weakens the protection:

  • Allow fallback to plain DNS. Your lookups leak exactly on strange networks, where it matters most. And it often doesn't even help: Windows falls back to your own DNS server, not the network's, and many portals block that too.
  • Turn encrypted DNS off for new networks. Then it only protects you at home.
  • Keep exceptions by hand. Turn it off, sign in, and remember to turn it back on. Every time.

CapPo doesn't encrypt anything itself: Windows does. CapPo is the reason you can leave it on. It notices the sign-in page, opens it in its own window, and closes the window once you're online.

Makes captive portals an offer they can't refuse.

How it works

  • The network's DNS, inside the sign-in window only. CapPo reads the DNS servers the network handed out (DHCP) and runs a tiny proxy inside the app that looks names up with them. Nothing outside your PC can reach it. Only CapPo's sign-in window uses that proxy. Everything else keeps using your encrypted DNS.
  • Your system DNS is never touched. CapPo doesn't change Windows' DNS settings, and it needs no administrator rights.
  • It checks the way Windows does. CapPo fetches Microsoft's connectivity test page through its proxy. If something else answers, a portal is in the way. It also supports networks that announce their portal (RFC 8910 / RFC 8908).
  • It notices when you're through. Once you're online, CapPo closes the window and flushes Windows' DNS cache, which still holds the failed lookups from before. Later it checks again, for portals that capture you again when a session runs out.

Always running, or on demand

CapPo can stay in the notification area and react to network changes at once. Or it can stay out of the way: Windows starts it when a network connects, for a check that takes about a second, and you only see it when there's a sign-in page.

Do you need it?

Windows 11 keeps DNS settings per Wi-Fi network, so where you set encrypted DNS decides it:

Where encrypted DNS is setOn a new hotel networkCapPo
For all Wi-Fi networks, unencrypted fallback offThe sign-in page never loadsNeeded
By policy, "Require DoH" (Group Policy or Intune)SameNeeded
Only for your home networkThe page loads, but nothing you look up there is encryptedNot needed
For all Wi-Fi networks, unencrypted fallback allowedWindows falls back to plain DNS on the server you set, not the network's. Many portals block that too; where they don't, your lookups go out unencryptedOften needed

CapPo is for Windows' built-in encrypted DNS. Apps that take over DNS themselves (VPNs, DNS filtering apps) have their own ways around portals.
